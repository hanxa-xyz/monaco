# /takehome-notebooks — bounded deep dives

Any combination of analyses can go infinitely deep; that is the paralysis. The antidote: pick from a
fixed menu of notebook types, each with a scope and a STOP condition. All are generated by builder
scripts (never hand-edited) via `dsviz.new_notebook/md/code/build_and_execute`, numbered `NN_name.ipynb`,
and every analytical cell prints its underlying table.

## The menu

**1 · Summary stats & QA** (Faire nb03 pattern)
One consistent metric set computed per entity, then aggregated across every dimension — apples to apples.
Owns the derived feature table (`outputs/<entity>_features.csv`) that all other notebooks share.
STOP when: every dimension has the same metric block and the feature table is written. No hypotheses here.

**2 · Time / cohort** (nb04 pattern)
Marketplace pulse; active-entity accounting (new/continuing/resurrected/churned); retention curves by
tenure AND by calendar (they confound — say which is which); maturation factors for in-flight cohorts;
seasonality flags. STOP when: the blended curves + one per-cohort comparison exist. Forecast models are
out of scope here.

**3 · Value concentration & segmentation** (nb05 pattern)
Lorenz/cumulative-share curves; define the value tier (smallest set producing X% of value — give tiers
neutral names, never pejorative); tier composition across every attribute; per-tier unit economics.
STOP when: the tier is defined, sized, and profiled. Interventions belong to /takehome-sizing.

**4 · ML-driven EDA** (nb06 pattern) — **now `/model`** (`src/monaco/modeling.py`, deterministic decisions, RF+XGB, tripwire); the rules below still apply.
X = everything observable by the end of the first window; y = the anchor metric. RandomForest + XGBoost
for comparable feature importances; partial-dependence looks at the top 5. Label everything
**exploratory, not causal** — importances rank hypotheses for the deep-dive notebook, they do not size
recommendations. STOP when: the ranked hypothesis list is written. No hyperparameter tuning ever.

## Shared rules
- Notebook 1 runs first; 2–4 import its feature table rather than recomputing.
- A hypothesis-by-hypothesis deep-dive notebook (hypothesis → test → verdict → so-what, with controls
  where selection bias is likely) is built ONLY after the human hypothesis review, one section per
  agreed hypothesis.
- Chart grammar per /takehome-charts throughout; dsviz `apply_style(dpi=110)` for notebooks.
